Lecture 6 introduces two ideas that initially seem separate. Recursion is a strategy for solving a problem by reducing it to smaller versions of itself. A dictionary stores relationships between unique keys and their associated values. The final example combines them: a dictionary remembers completed recursive work so the program does not calculate the same answer repeatedly.

Prof. Eric Grimson frames recursion in two ways. Algorithmically, it is a divide-and-conquer or decrease-and-conquer design technique. Semantically, it is a function calling itself. A correct recursive solution needs a simple stopping case and a recursive step that makes real progress toward it.

01

Recursion reduces

A recursive function trusts a smaller version of the same problem, then combines that result into the answer for the current input.

Core question: What smaller input moves me toward a case I can solve directly?

02

Dictionaries map

A dictionary associates each unique, hashable key with a value, making direct lookup clearer than coordinating parallel lists.

Core question: What meaningful key identifies the value I need?

1. The three requirements of recursion

Recursion is not simply “a function that calls itself.” Without a disciplined structure, that description permits a function to call itself forever. A useful recursive design has three parts:

Base caseA small input whose answer can be returned directly without another recursive call.
Recursive caseA rule that expresses the current answer using a smaller version of the same problem.
ProgressEvery recursive call moves closer to a base case, guaranteeing that the chain can terminate.
def multiply(a, b):
    """Return a times positive integer b using repeated addition."""
    if b == 1:
        return a
    return a + multiply(a, b - 1)

print(multiply(5, 4))  # 20

The base case solves a × 1 directly. The recursive case rewrites a × b as a + a × (b - 1). Because b decreases by one on every call, a positive starting value must eventually reach 1.

2. Iteration and recursion can express the same computation

An iterative algorithm keeps its progress in state variables that are updated by a loop. A recursive algorithm keeps progress in a chain of function calls. Factorial makes the comparison clear because n! can be built either by multiplying upward or by reducing n! to n × (n - 1)!.

Iterative factorial

def factorial_iter(n):
    product = 1
    for value in range(1, n + 1):
        product *= value
    return product

Recursive factorial

def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)

Both functions return the same result for non-negative integers. The recursive version closely matches the mathematical definition and can be easier to reason about. The iterative version avoids the overhead and depth limits associated with many function calls. Recursion can be efficient for the programmer without necessarily being efficient for the computer.

3. Every recursive call creates a new scope

Calling factorial(4) does not repeatedly overwrite one variable named n. Each call creates a separate local environment with its own binding: 

factorial(4)
4 * factorial(3)
4 * 3 * factorial(2)
4 * 3 * 2 * factorial(1)
4 * 3 * 2 * 1
24

The calls first descend toward the base case. The base case returns 1, and control then unwinds through the waiting scopes: factorial(2) returns 2, factorial(3) returns 6, and factorial(4) returns 24.

Tracing habit: Separate the downward call phase from the upward return phase. A recursive expression cannot finish until the smaller call inside it returns.

4. Inductive reasoning explains correctness

The logic behind a recursive proof resembles mathematical induction. First, show that the function is correct for the base case. Then assume it correctly solves a smaller input and show that the recursive step turns that smaller answer into the correct answer for the current input.

For multiply(a, b):

  1. Base: When b == 1, returning a is correct.
  2. Assumption: Trust that multiply(a, b - 1) correctly returns a × (b - 1).
  3. Step: Adding one more a produces a × b.
  4. Termination: Repeatedly subtracting one from positive b eventually reaches the base case.

This changes how I read recursive code. I do not need to mentally expand every possible call to understand the algorithm. I need to verify the base case, the smaller problem, the combination step, and the guarantee of progress.

5. Divide and conquer with a palindrome

A palindrome reads the same forward and backward. After normalizing the text, the recursive insight is that a string is a palindrome when its outer characters match and its inner substring is also a palindrome. 

def is_palindrome(text):
    def letters_only(value):
        result = ""
        for character in value.lower():
            if character in "abcdefghijklmnopqrstuvwxyz":
                result += character
        return result

    def check(value):
        if len(value) <= 1:
            return True
        return value[0] == value[-1] and check(value[1:-1])

    return check(letters_only(text))

print(is_palindrome("Able was I, ere I saw Elba"))  # True

The base case covers an empty string or a single character. The recursive case removes two characters, so the problem becomes smaller on every call. The use of and also short-circuits: when the outer characters differ, Python can return False without checking the middle.

This is divide and conquer in a compact form: solve a difficult problem by reducing it to an easier subproblem and combining that result with a small amount of work.

6. Fibonacci reveals overlapping subproblems

In the lecture's rabbit-population model, the count for month n is the sum of the counts from the previous two months. That definition translates directly into recursive code: 

def fibonacci(n):
    """Return the lecture's Fibonacci value for non-negative n."""
    if n == 0 or n == 1:
        return 1
    return fibonacci(n - 1) + fibonacci(n - 2)

print(fibonacci(6))  # 13

The code is clear, but its call tree repeats work. Computing fibonacci(6) asks for fibonacci(5) and fibonacci(4). The first branch also calculates fibonacci(4), so the same result is rebuilt many times.

This is an overlapping subproblem: different branches need the answer to the same smaller input. The lecture later uses a dictionary to remember those answers.

7. Dictionaries map keys directly to values

Before dictionaries, related data might be stored in parallel lists. That approach requires every list to stay the same length and forces the program to coordinate values through matching integer indexes. A dictionary stores each relationship as one key-value pair. 

grades = {
    "Ana": "B",
    "John": "A+",
    "Denise": "A",
    "Katy": "A",
}

print(grades["John"])  # A+

grades["Sylvan"] = "A"
grades["Ana"] = "B+"
del grades["Katy"]

print("Denise" in grades)  # True

Bracket lookup uses a key rather than a numeric position. Assigning a new key adds a pair, assigning an existing key replaces its value, and del removes the pair. Dictionaries are mutable, so these operations change the original dictionary object.

8. Dictionary rules and safe lookup

Keys are uniqueAdding an existing key updates its value rather than creating a duplicate key.
Keys are hashableStrings, numbers, and suitable tuples can be keys; mutable lists and dictionaries cannot.
Values are flexibleValues may repeat and can be immutable or mutable objects, including lists and nested dictionaries.

Direct lookup with a missing key raises a KeyError. Use membership testing when absence needs special handling, or use get() to supply a default value. 

inventory = {"cables": 4, "adapters": 2}

if "cables" in inventory:
    print(inventory["cables"])  # 4

print(inventory.get("monitors", 0))  # 0
Python version update: The Fall 2016 lecture used Python 3.5 and correctly taught that dictionary order was not guaranteed. In current Python, insertion order has been guaranteed since Python 3.7. A dictionary is still conceptually a mapping rather than a sequence indexed by position.

9. Iterate through keys, values, and pairs

A basic for loop over a dictionary visits its keys. The views returned by keys(), values(), and items() provide explicit ways to traverse the data. 

grades = {"Ana": "B", "John": "A+", "Denise": "A"}

for student in grades:
    print(student, grades[student])

for student, grade in grades.items():
    print(student, grade)

The second form unpacks each (key, value) pair and is usually the clearest choice when both pieces are needed. As with lists, changing the size of a dictionary during iteration can cause errors or skipped work, so structural mutations should be handled carefully.

10. Frequency dictionaries turn observations into counts

A frequency dictionary maps each distinct item to the number of times it appears. The first occurrence creates a key with count 1; later occurrences increment the existing value. 

def word_frequencies(words):
    counts = {}

    for word in words:
        if word in counts:
            counts[word] += 1
        else:
            counts[word] = 1

    return counts

topics = ["recursion", "dictionary", "recursion", "cache"]
print(word_frequencies(topics))
# {'recursion': 2, 'dictionary': 1, 'cache': 1}

The dictionary eliminates the need to know every possible word in advance. Each observed word becomes its own key, and the associated integer stores the accumulated count.

The lecture applies this pattern to song lyrics, then searches the resulting values to identify the most frequent words. The same structure appears in log analysis, vote counting, inventory summaries, and many data-processing tasks.

11. Memoization connects recursion and dictionaries

Memoization stores the result of a completed computation and reuses it when the same input appears again. A dictionary is a natural cache: the function input becomes the key and the calculated answer becomes the value. 

def fibonacci_memo(n, memo):
    if n in memo:
        return memo[n]

    memo[n] = (
        fibonacci_memo(n - 1, memo)
        + fibonacci_memo(n - 2, memo)
    )
    return memo[n]

known = {0: 1, 1: 1}
print(fibonacci_memo(6, known))  # 13

Every new value is computed once and saved. Later branches perform a dictionary lookup instead of expanding another recursive subtree. The lecture reports that its basic fib(34) example makes 11,405,773 recursive calls, while the dictionary-backed version makes only 65.

This optimization is safe when the function produces the same output for the same input and does not depend on changing external state. Memoization is the point where the lecture's two halves become one design: recursion defines the problem, and the dictionary prevents repeated work.

Practice lab

MIT OpenCourseWare does not provide an in-class question set for Lecture 6, so I created six original exercises from the lecture's examples. Try tracing the calls and data structures before opening each explanation.

01 Trace the call and return phases 
def power_of_two(n):
    if n == 0:
        return 1
    return 2 * power_of_two(n - 1)

print(power_of_two(3))

Answer: The output is 8. Calls descend through inputs 3, 2, 1, and 0. The base case returns 1, then the waiting calls return 2, 4, and finally 8.

02 Repair the missing base case 
def countdown(n):
    print(n)
    return countdown(n - 1)

Answer: The function never stops on its own because every call creates another call. One repair is:

def countdown(n):
    print(n)
    if n == 0:
        return
    countdown(n - 1)

The recursive call now moves toward 0, and the base case returns without making another call.

03 Identify the smaller palindrome problem

When checking whether "racecar" is a palindrome, what recursive input follows the first successful outer-character comparison?

Answer: The next input is "aceca". The outer r characters match, so the algorithm removes them and asks the same question about the smaller middle substring.

04 Trace dictionary mutation 
inventory = {"usb": 2, "cable": 3}
inventory["usb"] += 1
inventory["mouse"] = 1
del inventory["cable"]

print(inventory.get("usb", 0))
print(inventory.get("cable", 0))

Answer: Python displays 3 and 0. The USB count is updated, a mouse entry is added, and the cable entry is deleted. get() returns the supplied default for the missing cable key.

05 Build a frequency map 
words = [
    "recursion",
    "dictionary",
    "recursion",
    "cache",
    "dictionary",
    "recursion",
]

What dictionary should word_frequencies(words) return?

Answer: {"recursion": 3, "dictionary": 2, "cache": 1}. Each unique word is a key, and its value records the number of occurrences.

06 Explain the memoization shortcut

Suppose the memo dictionary already contains {0: 1, 1: 1, 2: 2, 3: 3}. What happens when fibonacci_memo(3, memo) is called?

Answer: The function immediately returns 3 from the dictionary. It makes no calls for 2 or 1 because the answer for key 3 has already been calculated.

Key takeaways

  • Recursion solves a problem by reducing it to smaller versions of the same problem.
  • A correct recursive function needs a base case, a recursive case, and guaranteed progress toward the base.
  • Every recursive call creates its own local scope, and results return as the call chain unwinds.
  • Inductive reasoning checks the base case and proves that a correct smaller answer produces a correct larger answer.
  • Recursion can express divide-and-conquer problems clearly, but a clear solution is not automatically computationally efficient.
  • Dictionaries are mutable mappings from unique, hashable keys to flexible values.
  • Membership tests and get() help avoid unexpected KeyError exceptions.
  • Frequency dictionaries provide a reusable pattern for counting observations.
  • Memoization uses a dictionary to cache recursive results and avoid repeated subproblems.
  • Modern Python dictionaries preserve insertion order, although the course's Python 3.5 environment did not guarantee it.
