Lecture 5 completed - five lectures into the 12-lecture series.

Part 1 introduced lists as ordered, mutable collections. This second part asks the question that makes mutability tricky: when a list changes, which names and which parts of the program can observe that change?

The key mental model is that a variable name does not contain a list. It points to a list object in memory. Two names can point to the same object, producing aliases and shared side effects. A clone creates another outer list object, allowing the two collections to change independently - with an important warning for nested lists.

01

Track identity

Two lists can contain equal values without being the same object. The crucial question is which names point to which object.

Core question: Is this a shared reference or a separate list?

02

Control side effects

A mutation can be useful and intentional, but every reference to that object will observe the change.

Core question: Who else can see this mutation?

1. Removing elements: position, value, or result

Python offers several removal operations because programs need different information. del removes by index, remove() searches for a value, and pop() removes an item while also returning it. 

queue = ["scan", "review", "deploy", "archive", "review"]

queue.remove("review")  # removes the first matching value
del queue[1]            # removes the item at index 1
last_task = queue.pop() # removes and returns the last item

print(queue)      # ['scan', 'archive']
print(last_task)  # review
del items[index]Removes the element at a known position and does not return it.
items.remove(value)Removes the first equal value. It raises an error when the value is absent.
items.pop()Removes and returns the final element by default; an index can be supplied.

All three operations mutate the original list. If the removed value is needed later, pop() makes that data flow explicit.

2. Convert between strings and lists

A string is immutable, while a list is mutable. Converting between them is useful when text needs to be separated, transformed, and assembled again. 

raw_topics = "mutation aliasing cloning"

words = raw_topics.split()
characters = list("clone")
summary = " → ".join(words)

print(words)
# ['mutation', 'aliasing', 'cloning']

print(characters)
# ['c', 'l', 'o', 'n', 'e']

print(summary)
# mutation → aliasing → cloning

list(text) separates every character. text.split(separator) divides text into meaningful pieces and uses whitespace when no separator is supplied. separator.join(items) connects a list of strings into one new string.

Direction matters: Call split() on the source string, but call join() on the separator that should appear between the resulting pieces.

3. Sorting: mutate the list or create a result

sort() and sorted() can produce the same ordering, but they do not have the same effect. The method list.sort() changes its list and returns None. The function sorted() returns a new sorted list and leaves its input unchanged. 

scores = [88, 72, 95, 81]

ranked = sorted(scores)

print(scores)  # [88, 72, 95, 81]
print(ranked)  # [72, 81, 88, 95]

scores.sort()
scores.reverse()

print(scores)  # [95, 88, 81, 72]

Mutating methods

sort() and reverse() change the list object on which they are called. Their return value is None.

New returned value

sorted(items) creates and returns a new list. The caller must save that returned value to use it later.

4. Names point to objects in memory

Assignment connects a name to an object. With an immutable value, an apparent “change” usually rebinds the name to a new object. With a list, an operation can instead modify the existing object. 

scores = [72, 84, 91]
current_scores = scores

current_scores.append(96)

print(scores)                    # [72, 84, 91, 96]
print(scores is current_scores)  # True

The assignment current_scores = scores does not copy any elements. It creates a second name for the same list object. The is operator checks object identity, so it confirms that both names point to one object.

This is different from equality. Two separate lists can satisfy left == right because their contents match while left is right remains False.

5. Aliasing makes changes visible through every name

An alias is another name for the same object. Mutating through either alias changes the single shared list, so reading through any other alias reveals the updated contents. 

original = ["bacon", "eggs"]
brunch = original

original.append("juice")
brunch.extend(["toast", "jam"])

print(original)
# ['bacon', 'eggs', 'juice', 'toast', 'jam']

print(brunch)
# ['bacon', 'eggs', 'juice', 'toast', 'jam']

No synchronization step occurs here. There is only one list. The two names are simply two routes to that same object, which is why mutations made through either route are shared.

Tracing habit: Draw names as arrows and objects as boxes. When two arrows reach the same box, expect a mutation through one name to be visible through the other.

6. Cloning creates an independent outer list

To change a list without affecting the original, create a clone. A full slice such as items[:] copies the references into a new outer list. The copy() method provides the same kind of shallow copy. 

original = ["scan", "review", "deploy"]
snapshot = original[:]

original.append("monitor")
snapshot[0] = "plan"

print(original)
# ['scan', 'review', 'deploy', 'monitor']

print(snapshot)
# ['plan', 'review', 'deploy']

print(original == snapshot)  # False
print(original is snapshot)  # False

The clone begins with the same element values, but it has a separate identity. Appending to one outer list or replacing one of its positions does not change the other.

7. A shallow clone does not copy nested objects

The word shallow matters. Slicing creates a new outer list, but nested mutable objects are still shared. Both outer lists can therefore point to the same inner list. 

original = [["Lance", 84], ["Maya", 91]]
snapshot = original[:]

snapshot[0][1] = 95

print(original[0])  # ['Lance', 95]
print(snapshot[0])  # ['Lance', 95]
print(original is snapshot)        # False
print(original[0] is snapshot[0])  # True

Replacing snapshot[0] would affect only the cloned outer list. Mutating snapshot[0][1], however, reaches the shared inner object. A correct memory diagram must show both outer lists pointing to the same nested lists.

8. Functions can produce mutation side effects

Passing a list to a function gives the function another reference to that object. If the function mutates its parameter, the caller observes the same changed list after the function returns. 

def add_result(results, value):
    results.append(value)

quiz_results = [82, 91]
add_result(quiz_results, 88)

print(quiz_results)  # [82, 91, 88]

This side effect can be intentional, but the function's name and documentation should make it clear. When the original should be preserved, clone first and return the new list. 

def with_result(results, value):
    updated = results[:]
    updated.append(value)
    return updated

quiz_results = [82, 91]
new_results = with_result(quiz_results, 88)

print(quiz_results)  # [82, 91]
print(new_results)   # [82, 91, 88]

9. Do not mutate the list being iterated over

A loop tracks its current position internally. Removing an element shifts later values to new indexes, but the loop still advances its counter. The item that moves into the current position can be skipped. 

values = [1, 2, 3, 4]
blocked = [1, 2]

for value in values:
    if value in blocked:
        values.remove(value)

print(values)  # [2, 3, 4] - the 2 was skipped

The safe pattern is to iterate over a clone while mutating the original. The loop's sequence stays stable even as the original list becomes shorter. 

values = [1, 2, 3, 4]
blocked = [1, 2]

for value in values[:]:
    if value in blocked:
        values.remove(value)

print(values)  # [3, 4]

This example connects every major idea in Part 2: mutation changes an object, aliases make that change visible elsewhere, and cloning can isolate the sequence used for safe traversal.

Practice lab

MIT's Lecture 5 questions combine sequential list operations with an aliasing trace. I used those themes to create the following original self-checks. Predict both the final values and which names share an object before opening each answer.

01 Trace three removal operations 
values = [3, 1, 3, 2]
values.remove(3)
last = values.pop()
del values[0]

print(values)
print(last)

Answer: values becomes [3], and last is 2. remove(3) deletes only the first matching 3; pop() then removes and returns the final value.

02 Split, update, and join 
text = "alias|clone|mutate"
parts = text.split("|")
parts[2] = "review"
result = " → ".join(parts)

print(result)

Answer: The output is alias → clone → review. split() creates a list of three strings, the assignment mutates that list, and join() creates a new string.

03 Compare sorted() and reverse() 
scores = [72, 91, 84]
ranked = sorted(scores)
scores.reverse()

print(scores)
print(ranked)

Answer: scores is [84, 91, 72], while ranked is [72, 84, 91]. sorted() created a new list before reverse() mutated the original.

04 Separate an alias from a clone 
original = ["a", "b"]
alias = original
clone = original[:]

alias.append("c")
clone[0] = "z"

print(original)
print(alias)
print(clone)

Answer: Both original and alias display ["a", "b", "c"] because they share one object. clone displays ["z", "b"] because it is a separate outer list created before the append.

05 Explain the skipped value 
numbers = [1, 2, 3, 4]

for number in numbers:
    if number < 3:
        numbers.remove(number)

print(numbers)

Answer: The result is [2, 3, 4]. Removing 1 shifts 2 into index 0, but the loop advances to index 1, where it sees 3. Iterating over numbers[:] would prevent the skip.

Key takeaways

  • del, remove(), and pop() all mutate a list but select and return information differently.
  • split(), list(), and join() convert between immutable strings and mutable lists.
  • sort() and reverse() mutate a list; sorted() returns a new list.
  • A variable name points to an object rather than containing the object itself.
  • Aliases are different names for the same object, so mutations are visible through every alias.
  • A slice such as items[:] creates a shallow clone with a separate outer-list identity.
  • Nested mutable objects remain shared after a shallow copy and can still produce side effects.
  • A function can mutate a list supplied by its caller, so side effects should be deliberate and clear.
  • Do not mutate the list being traversed; iterate over a clone when the original must change.
